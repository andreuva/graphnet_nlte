# GNN Emulator for NLTE Stellar Atmospheres
This repository implements a **Graph Neural Network (GNN)** to accelerate the calculation of atomic populations in stellar atmospheres under **Non-Local Thermodynamic Equilibrium (NLTE)** conditions.

## The Problem: The High Cost of NLTE
In modern astrophysics, simulating the outer layers of stars (like the Sun's chromosphere) requires realistic 3D Magnetohydrodynamic (MHD) models. However, interpreting these models to produce synthetic spectra—what we actually observe—is computationally prohibited by the **NLTE problem**.

1. **Non-Locality:** Unlike the deep solar interior, the outer atmosphere is thin. Light travels long distances before being absorbed. This means the state of an atom at point A depends on the radiation field coming from points B, C, and D far away.
2. **Computational Bottleneck:** Traditional solvers (like *Lightweaver* or *RH*) must solve coupled radiative transfer and statistical equilibrium equations iteratively. Doing this for every voxel in a high-resolution 3D simulation frame can take hundreds of thousands of CPU hours.
3. **The Consequence:** We often rely on simplifications (like 1D approximations) or wait days for a single snapshot to process.

## The Solution: A Geometric Deep Learning Approach
This project replaces the expensive iterative solver with a **Graph Neural Network (GNN)** surrogate model. By treating the atmospheric grid as a graph, the model learns the "non-local" physics directly from data.

### 1. Representing the Atmosphere as a GraphStandard Convolutional Neural Networks (CNNs) struggle with the specific geometry and varying density of stellar atmospheres. Instead, we use a graph approach:

* **Nodes:** Each grid point in the simulation (voxel) is a node.
* **Edges:** Nodes are connected to their neighbors within a physical radius. This structure explicitly models the "region of influence" where radiation couples local plasma properties.
* **Features:** Each node contains local physical parameters: Temperature (T), Electron Density (n_e), Velocity (v), and Magnetic Field (B).

### 2. The Learning ProcessThe GNN is trained on "ground truth" data generated by rigorous radiative transfer codes.

* **Input:** A snapshot of physical atmospheric parameters (Temperature, Density, etc.).
* **The "Black Box":** The GNN passes information along edges (Message Passing), allowing nodes to "see" their neighbors and update their internal state based on the surrounding environment.
* **Output:** The model predicts the **atomic populations** (or departure coefficients) for specific energy levels (e.g., Hydrogen, Calcium) almost instantaneously.

### 3. ImpactOnce trained, the GNN can predict a full 3D snapshot in seconds rather than hours, enabling fast spectral synthesis and real-time analysis of solar simulations.

## Repository Architecture
While the focus is on the physics, the code is structured to handle the full pipeline from data ingestion to spectral synthesis.

### Core Components* **`conf.dat`**: The "Control Center". This configuration file dictates the physics (grid size, radius of influence) and the ML hyperparameters (learning rate, layers).
* **`gnn_train.py`**: The training engine. It loads the 3D atmospheric grids, builds the graphs on-the-fly, and optimizes the network to minimize the error between predicted and true populations.
* **`Dataset.py`**: The "Graph Builder". This script handles the complex task of converting 3D Numpy arrays into PyTorch Geometric graph objects, calculating Euclidean distances and edge connections.

### Analysis & Synthesis* **`gnn_inference.ipynb`**: The testing ground. Use this to load a trained model, run it on unseen simulation snapshots, and visualize the error distribution.
* **`synthesis.ipynb`**: The bridge to reality. This notebook takes the GNN's predicted populations and feeds them into **Lightweaver** to generate actual spectral lines (e.g., Ca II H&K lines). This validates whether the ML approximation produces realistic physics.

## 🚀 Quick Start
### 1. PrerequisitesYou will need a Python environment with `torch`, `torch_geometric`, and `lightweaver`.

### 2. ConfigureEdit `conf.dat` to point to your training data (Bifrost or similar MHD simulation grids):

```ini
[data]
datadir = '../path/to/simulation/data'

```

### 3. Train the ModelRun the training script to teach the GNN the relationship between plasma parameters and atomic populations:

```bash
python gnn_train.py

```

### 4. Synthesize SpectraOpen `synthesis.ipynb` to generate spectral lines from your model's predictions and compare them against the ground truth.
